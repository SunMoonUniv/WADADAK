**추정 소모 칼로리 — 사용자 확정**

- `kcal = weightKg × distanceM / 1000`. 예: 65kg × 5km = 325kcal.
- 체중은 시작 시점 자료로 고정한다. 사용 가능한 체중이 없으면 null이고 화면은 `—`다. 이후 체중 변경·신체 정보 편집으로 과거 결과를 다시 계산하지 않는다. 과거 START의 체중 누락도 소급 보완하지 않는다.
- distanceM은 기존 정상 측정한 전체 개인 세션 거리다. 코스 기준 거리/코스 인정 거리나 표시용 km 반올림을 사용하지 않는다. 실제 이어 달린 자유 구간도 개인 세션 거리의 일부다. 수동 정지 중 이동·누락 GPS를 새로 인정하지 않는다.
- 원래 소수 kcal를 보존하고 표시만 정수로 반올림한다. 주행 중 앱 값은 잠정치이고, 종료 후 동일한 시작 체중과 서버 검증 거리로 확정한다.
- 결과·측정 화면에는 추정값임을 표시한다. 기본 5개 터치 전환 후보는 늘리지 않는다. MY 합계는 저장된 값의 합이며 미상 기록이 섞이면 0으로 대체하지 않고 `—`다.
- 앱은 성공한 가입·본인 profile 조회/저장에서 동의된 체중만 계정별 보안 저장소에 캐시한다. 시작 시 캐시가 없으면 측정 전 최대 2초로 본인 profile 읽기를 시도하며 실패하면 칼로리만 비운다. 자유 러닝의 오프라인 시작은 계속 허용한다.
- 코스 시작 요청과 고스트 시작 승인의 기기 저장 자료에도 선택 체중을 넣어, 응답 유실·재시도·60초 복구가 다른 체중을 사용하지 않게 한다. 서버 고스트 승인 요청의 공개 필드는 변경하지 않는다.

**입력·결과와 호환**

- 업로드 원본의 START에 선택 `weightKg`. 유한한 20~300kg만 허용하며 다른 입력 종류에 이 필드를 넣으면 기존 INVALID 처리한다. 서버에서 입력을 읽고 idempotent하게 보존한다.
- 본인 결과/목록 `metrics`의 선택 `weightKg`와 `estimatedCaloriesKcal`. 과거 기록에서는 null이다. 공개 고스트 재생·비교 DTO나 랭킹 이벤트에는 추가하지 않는다.
- 서버는 기존 JSON payload/result/summary를 사용하므로 서버 DB 컬럼/마이그레이션이 없다. 원래 DTO 생성자 및 누락 필드를 유지한다.
- 기기 SQLite v6: sessions.guidance_state, withdrawn_run_owners. 기존 자료는 보존한다. 탈퇴 owner에는 sessions/run_settings/run_deletions/course_start_intents/ghost_start_intents/ghost_closures의 INSERT/UPDATE를 차단한다. 삭제 ledger에는 재생성 차단용 owner 식별자만 남기고 GPS·승인·설정은 삭제한다.
- rollout: 새 서버를 먼저 적용하고 새 앱을 적용한다. 이 구현 작업은 운영 서버 배포/휴대폰 설치를 포함하지 않는다.
