# 실시간 누적 고도와 균형형 GPS 보정

2026-10-20 사용자 선택: 고도와 지도 경로·거리 모두 보정하며, 작은 언덕과 회전을 보존하고 명백한 튐을 줄이는 균형형을 사용한다. 같은 날 정책 대조 후 큰 튐 구간의 재연결 금지를 명시했고, 정책 문서 공통 2와 개발 정책 v3의 실시간 고도·PACE_V3 계약에 반영했다.

## 실시간 고도

- `FreeRunController`가 진행 중인 원본과 확인된 이동 구간으로 누적 상승 고도를 계산해 기존 전체 지표 화면에 전달한다. 약 3초 간격으로 새 입력을 반영하고 일시정지·재개 시 최신 자료로 갱신한다. 화면 재조회나 새 측정 없는 타이머는 캐시를 사용한다.
- `RunSnapshot.liveElevationGainM`은 화면용 잠정값이다. 최종 결과·서버 업로드 요약의 `resultStats`와 분리한다. 종료 시 전체 원본으로 최종 통계를 계산한다. 뒤에 들어온 자료로 마지막 구간이 재평가되므로 잠정값과 최종값은 조금 다를 수 있다.
- 기존 RESULT_V3 고도 계산을 재사용한다. 기압 자료 우선, 측정 불가 이동 구간만 GPS 고도로 대체한다. 5초 중앙값과 지속성·수평 이동 확인, 기압 최소 1.5m 기준을 유지한다. GPS는 고도 정확도에 따른 더 큰 문턱을 사용한다. 센서 없는 기기에서 작은 언덕이 모두 반영된다고 보장하지 않는다.
- 자료 부족은 `—`, 충분히 측정됐지만 상승이 없으면 `0 m`다. 정지·일시정지·GPS 공백 전후의 높이를 연결하지 않는다. 원본 압력·GPS 고도는 변경하지 않는다. 라이브 계산에서는 사용하지 않는 최고 페이스 검색을 생략한다.

## 경로·거리: PACE_V3

- 새 러닝의 START reason은 `PACE_V3`다. `PACE_V2`와 이전 기록은 당시 거리·시간·경로 계산을 그대로 재생한다. 앱과 서버의 `MotionPace`가 같은 규칙을 사용한다.
- 원래 위치 품질(15m), 이동 확인, 정지 확인, 10초 공백, 12m/s 상한은 유지한다. 보정 전 연속 원본 GPS에서 품질·시간 간격·속도 경계를 먼저 검사하고 구간을 끊는다. 큰 튐 점을 제거한 뒤에도 경계 앞뒤를 지도·거리·페이스·고도 분석에서 다시 연결하지 않는다. 경로 전체를 직선화하거나 회전 각도만으로 좌표를 제외하지 않는다.
- 양 끝의 신뢰 가능한 GPS 속도(기존 기준: 속도 오차 0 초과~0.5m/s 이하)가 있고, 시간 간격이 0 초과~3초일 때만 추가 판정한다. 이동 거리가 `(양 끝 속도와 속도 오차의 평균 × 시간) + max(6m, 양 끝 위치 오차 합)`을 초과하면 의심 좌표 하나를 잠시 보류한다.
- 원본의 강제 단절 경계가 없는 구간에 한해, 다음 GPS에서 두 번째 이동도 위 보정 기준을 초과하고, 앞뒤 정상 좌표의 직선 이동은 속도 범위 안에 있으며, 우회 길이가 직선보다 `max(8m, 세 좌표 위치 오차 합)`만큼 길면 가운데 한 점을 분석 경로에서 제외한다. 원본은 저장·업로드한다. 다음 좌표가 정상임을 확인할 때까지 보통 한 GPS 표본만큼 지연될 수 있다.
- 고립된 튐이 확인되지 않으면 기존 계산으로 돌려보낸다. 속도 정보 부족·낮은 신뢰도·긴 표본 간격·두 점 이상 지속된 위치 이탈은 추가 필터만으로 복원하지 않는다. 마지막 의심 좌표를 확인하기 전에 일시정지·종료·공백이 오면 해당 좌표를 경로에 확정하지 않으며 경계를 넘어서 연결하지 않는다.
- 기압·케이던스·SEGMENT_END 이벤트는 다음 GPS 확인을 방해하지 않는다. 코스 완주·인정 거리 판정 규칙은 변경하지 않는다.

## 적용 순서와 검증 범위

- **서버를 먼저 배포한 뒤 새 앱을 적용한다.** 이전 서버는 PACE_V3를 알지 못해 과거 계산으로 처리할 수 있다. 코드 적용·APK 빌드와 운영 배포·휴대폰 설치는 별도다.
- `free_motion_v3.json`의 앱·서버 공통 23개 시나리오: 10m·60m 고립 튐, 시작·끝 근처 튐, 급회전, 왕복, 빠른 달리기, 느린 걷기, 속도 정보 누락/불확실, 긴 간격, 두 점 이탈, 이전 V2, 센서 이벤트, 일시정지, 낮은 위치 정확도, 보류 후 큰 튐·긴 공백·불량 위치·명시적 GAP, 한쪽만 큰 튐 및 연속 큰 튐. 원본의 큰 튐 시간 구간이 같은 경로 구간에 들어가지 않는지도 검사한다.
- 기존 28개 기압 시나리오에서 라이브/최종 필터 공유·일시정지 갱신·최종 통계 캐시 분리를 확인한다. 실제 기록 화면 전달, 새 러닝 초기화, 화면 갱신 및 0/미측정 구분도 확인한다.
- 서버 임시 DB에서 PACE_V3 업로드·원본 좌표 보존·보정된 거리/경로 저장·동일 업로드 재시도를 확인한다. 실제 야외 주행 정확도 검증은 별도다.
