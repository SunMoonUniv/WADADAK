# 고스트 재생 계약 v1 · 첫 구현

상태: 구현·검증용 계약 초안. run 담당 공동 리뷰 대상이며 외부 모듈 계약 승인·운영 배포 완료를 뜻하지 않는다.

## 범위와 소유권

첫 범위는 **내 서버 확정 코스 완주 기록 1건 → 원본/코스 스냅샷 → 총 소요시간 재생**이다. F9는 run 안에서 구현한다. 기존 CourseJudge/Tracker를 재사용하고 판정·거리·GPS 품질 기준은 바꾸지 않는다. 타인 조회, 공개 후보, 시작 시 상대 고정, 승패 저장, 60초 재개, UI 연결은 후속 범위다. 비자발적 중단으로 최종 미완주면 모두 무효라는 10/26 결정도 후속 판정 단계에서 적용한다.

다른 모듈용 새 공개 인터페이스·호출·이벤트는 없다. 새 REST DTO는 run/internal/RunContracts에 둔다. 따라서 타 모듈용 스텁/설정과 호출·이벤트 허용 목록을 추가하지 않는다. 본인만 조회하므로 공개 설정을 우회하는 타인 제공도 없다. 기존 스텁 설정은 유지한다.

## REST

`GET /api/v1/runs/records/{id}/ghost-playback` · 인증 필수 · ApiResult<GhostPlayback>.

- JWT sub의 소유권을 저장된 세션에서 확인한다. 다른 계정·없는 기록·삭제·탈퇴 기록은 기존 RUN-002(404).
- 본인 기록이지만 미완주/자유 러닝/원본 부족/버전 불일치/품질 초과면 정상 응답에 eligible=false와 unavailableReasons를 반환한다. 완주 여부를 수정하지 않는다.
- 서버 저장 원본과 준비 당시 코스 스냅샷만 사용한다. 코스 서비스 재조회·공개 후보 조회·타 스키마 조회 없음.
- 조회는 생성/재등록/이벤트 발행/결과 갱신을 하지 않는다. 삭제·탈퇴와 동일한 회원→세션 잠금 순서로 읽기를 직렬화한다.
- 최초 범위는 선택한 1건의 상세 파생 응답이다. 목록/후보 호출에서 원본을 전부 읽지 않는다. 재생 자료 캐시/별도 저장·30일 상세 사본 정리는 실제 대결 스냅샷 저장 단계에서 추가한다. 이번에는 상세 사본을 새로 저장하지 않는다.

## 응답 의미

- version: GHOST_PLAYBACK_V1. 기존 policyVersion·PACE 버전을 바꾸지 않는다.
- sourceRecordId, course(기존 CourseSnapshot), sourcePolicyVersion, sourceCalculationVersion, courseElapsedSeconds(저장된 비교 시간).
- durationMs: 서버가 최초 완주를 확인한 표본의 단조 경과 ms. 완료 시각 UTC의 차이로 대체하지 않는다. 이후 자유 러닝은 제외.
- eligible, unavailableReasons(복수 사유), quality(activeDurationMs, gapMs, maxGapMs).
- samples: elapsedMs와 nullable coursePositionM. 원본 GPS의 코스 누적 위치이며 연결 불가 경계의 정확한 표본 시각도 표현한다.
- spans: fromMs/toMs, nullable fromPositionM/toPositionM, state(TRACKED/PAUSED/UNKNOWN). [fromMs,toMs) 구간이며 0~durationMs 전체를 덮는다. TRACKED는 기존 추적기가 연결을 확인한 구간, PAUSED는 확인된 위치의 수동 정지, UNKNOWN은 확인 불가다. 동일한 선형 구간만 합칠 수 있다.
- 위치는 코스 경로 시작부터 누적 m다. 방향은 경로 좌표 순서이며 별도 방향 필드를 추가하지 않는다.

재생 불가 사유: NOT_COMPLETED(서버 확정 코스 완주 아님), MISSING_COURSE_SNAPSHOT, COURSE_VERSION_MISMATCH, UNSUPPORTED_SOURCE_POLICY, MISSING_SOURCE_INPUTS, SOURCE_RESULT_MISMATCH, NO_ACTIVE_DURATION, CONTINUOUS_GAP_EXCEEDED, TOTAL_GAP_EXCEEDED, AMBIGUOUS_POSITION, PAUSE_POSITION_UNAVAILABLE, FINISH_POSITION_UNAVAILABLE. 자료·버전 검증 실패는 빈 재생 자료를, 품질 제한은 검사 가능한 본인 파생 자료와 복수 사유를 제공한다. 앱은 eligible=false인 자료를 재생하지 않는다.

## 공백·정지·조회 규칙

- 10,000ms 초과 GPS 연결 금지를 유지한다. 연결되지 않은 양쪽 확인 표본 사이 **전체 구간**을 UNKNOWN으로 두며, 중간 GAP/불량 표본이 겹쳐도 한 번만 센다. 처음/마지막 확인 표본 밖 구간도 UNKNOWN이다.
- PAUSE~RESUME는 총 소요시간에 포함하되 GPS 공백 분모/분자에서 제외한다. 정지 위치는 직전 유효 표본이 신선하고 중간 GAP/불량 경계가 없을 때 유지한다. 정지 위치까지 확인할 수 없으면 선택 제한 사유를 제공한다.
- 연속 UNKNOWN 중간에 수동 정지가 있으면 그 시간만 빼며 공백 길이를 인위적으로 분할하지 않는다. 정상 TRACKED 구간에서 연속 공백 누적을 종료한다.
- maxGapMs ≤30,000, gapMs/activeDurationMs ≤5%를 동시에 만족해야 한다. 정수 ms와 정수 곱 비교를 사용하고 표시 반올림은 쓰지 않는다. 분모가 0이면 사용 불가.
- 끝내 해소되지 않은 교차/왕복 위치 대응은 AMBIGUOUS_POSITION으로 제한한다. 코스 버전/기존 완주 시각/정수 초가 재현되지 않으면 기존 결과를 보존하고 SOURCE_RESULT_MISMATCH 등으로 제한한다.
- 앱은 경과 총 소요 ms로 조회한다. 러너 정지와 무관하게 시간이 진행하며 상대 PAUSED 구간은 위치 유지. UNKNOWN을 직선으로 연결하거나 마지막 위치로 현재 격차를 만들어 내지 않는다. 정확한 유효 sample 시각의 위치는 사용할 수 있다.
- 재생 종료 이후는 FINISHED와 실제 마지막 확인 위치다. 마지막 표본을 임의로 코스 전체 길이로 늘리지 않는다. eligible=false는 UNAVAILABLE, 음수 시간은 시작 전이다.
- 기존 속도 상한을 넘은 원본 위치 튐은 코스에 투영됐더라도 정확한 표본 시각의 신뢰 위치로 노출하지 않는다. 정지·재개·GAP 경계는 속도 계산으로 다시 연결하지 않는다. 마지막 완주 표본의 위치도 신뢰할 수 없으면 재생 후보에서 제한하며 기존 서버 완주 결과는 보존한다.
- 최초 정방향 도달 시각은 TRACKED 정방향 구간에서만 선형 시간 대응하고 가장 이른 값을 사용한다. 공백·역행 구간에서 도달 시각을 추정하지 않는다. 완주/승패 정수 초 규칙을 새로 확정하지 않는다.

## 공통 샘플과 검증

run/fixtures/ghost_playback_v1.json은 개인정보 없는 합성 좌표 입력과 기대 재생 구간·시각별 조회값을 함께 담는다. Java 생성기와 Dart 재생기가 같은 파일을 읽는다. 정상·30초 수동 정지·공백 및 정확한 경계·모호한 위치·역행·자유 러닝 제외를 검증한다.

저장 통합 검증은 기존 Testcontainers 별도 DB에서 기존 업로드→서버 판정→GET→Dart 재생 계약을 확인한다. 일반 개발 DB/본인 실제 GPS를 테스트 데이터로 덮어쓰지 않는다. 실제 개인 완주 기록이 없으면 합성 입력의 DB 저장·재조회 검증과 실제 개인 기록 재생 완료를 구분해 기록한다.

## 공동 리뷰와 후속 연결

공유 변경: CourseJudge의 분석 결과 노출(기존 judge 반환/규칙 유지), RunContracts의 응답 추가. 기존 코스 판정·자유 측정·직렬화·모듈 경계 회귀를 확인한다. core·ranking·member·MY·지도·기존 입력 enum·DB 스키마는 이번 범위에서 변경하지 않는다. REST 명세는 Swagger에 반영하고 앱 화면 연결은 이후 명세 확인 뒤 진행한다. 계약 리뷰와 구현은 별도 검토가 가능하도록 변경 목록을 인계한다.

DB에 저장한 합성 완주 1건의 실제 API 응답은 통합 테스트가 build/ghost-playback-check/own-completed-record.json으로 내보낸다. 앱 폴더에서 dart run tool/verify_ghost_playback.dart ../../BackEnd/build/ghost-playback-check/own-completed-record.json으로 같은 응답을 재생해 볼 수 있다. 이 파일은 테스트 증거이며 개인 실주행 데이터나 운영 DB 사본이 아니다.
