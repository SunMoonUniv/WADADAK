## 복구

- 환경: Docker Desktop 4.83.0, Docker Engine 29.6.2, Windows의 WSL2 Linux 엔진.
- 오류: `initializing Inference manager` 단계에서 `Docker/run/dockerInference` 소켓을 지우지 못하는 Windows 오류 1920으로 엔진이 시작되지 않았다. 해당 소켓과 다른 런타임 소켓의 마지막 수정 시각은 2026-10-13이었다.
- Docker를 `docker desktop stop --force --timeout 20`으로 종료하고 프로세스 종료를 확인했다.
- 통신 소켓만 들어 있음을 확인한 두 폴더의 이름을 바꿔 보존하고 원래 경로에 빈 폴더를 생성했다.
  - `C:/Users/USER/AppData/Local/Docker/run` → `run.stale-20261019-barometer`
  - `C:/Users/USER/AppData/Local/docker-secrets-engine` → `docker-secrets-engine.stale-20261019-barometer`
- Docker를 다시 시작해 새 소켓 생성과 엔진 API 정상 응답을 확인했다.
- 설정 변경·업데이트·재설치·초기화·이미지/컨테이너/볼륨 삭제는 하지 않았다. 기존 WSL 데이터 디스크도 그대로 유지했다. 문제 소켓은 백업 폴더에 남겨 두었다.
- 동일한 오류와 부모 폴더 이름 변경 방식은 [Docker 이슈 #554](https://github.com/docker/desktop-feedback/issues/554), [관련 이슈 #448](https://github.com/docker/desktop-feedback/issues/448)에 보고돼 있다. 이번 환경에서는 설정을 변경하지 않고 정상 시작됐다.

## 통합 검증

실제 프로젝트 `C:/Users/USER/IdeaProjects/WADADAK/BackEnd`에서 Java 21을 사용해 실행했다.

```text
./gradlew.bat test --offline --tests "com.wadadak.run.internal.recording.*" --console=plain
```

- `RunIngestionTest`: **18개 통과**, 실패 0, 오류 0, 건너뜀 0. `BUILD SUCCESSFUL`.
- Spring Modulith의 run 모듈 단독 기동 및 Testcontainers의 별도 `postgis/postgis:17-3.5` DB를 사용했다. 기존 개발 DB 컨테이너를 시작하거나 그 DB의 테이블을 테스트에 사용하지 않았다.
- 새 기압 통합 사례: HTTP 업로드 → 기압/센서 시각 원본 보존 → 서버 상승 고도 3m 계산 → 목록 요약 보존 → 재시도 시 등록 시각 유지 → 원본 변조 충돌 → 이전 V2 결과의 응답 보완과 저장값 유지 → 소유권 검사 → 삭제 후 원본 제거와 늦은 업로드 차단.
- 잘못된 압력·상태·미래 시각·측정 시각 누락·GPS 입력에 섞인 압력 필드를 거부하고 트랜잭션이 롤백되는 것을 확인했다.
- 나머지 기존 업로드 누락·동시 요청·중복 이벤트·탈퇴·목록 조회·고도 원본 호환 사례도 함께 통과했다.
- 기존 서버 계산/판정/모듈 경계 88개와 이번 DB 통합 18개를 합해 관련 검증 **106개**가 통과했다. 앞서 완료한 앱 314개·정적 분석·Android 빌드 결과는 유지되며 이번에는 제품 코드를 바꾸지 않아 재실행하지 않았다.
