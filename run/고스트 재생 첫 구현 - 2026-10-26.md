# 고스트 재생 첫 구현 · 2026-10-26

브랜치: feature/F09-ghost-playback · 상태: 로컬 구현·검증 완료, 공동 리뷰/PR/배포 전.

## 구현한 흐름

본인 서버 확정 코스 완주 기록 1건을 선택해 원본과 준비 당시 코스 경로로 재생 자료를 만든다. GET /api/v1/runs/records/{id}/ghost-playback은 JWT 소유권을 검사하고, 총 소요 ms의 위치·정지·공백과 재생 적합성 사유를 ApiResult로 돌려준다. 기존 기록·원본·정수 초·등록 시각·랭킹·이벤트는 변경하지 않는다.

Dart의 GhostPlayback은 이 응답을 읽어 특정 경과시간의 위치/정지/확인 불가/도착 상태와 최초 정방향 도달 시각을 계산한다. 화면·타이머·측정기를 만들지 않는 순수 계산이며 러너의 일시정지로 고스트 시간 축을 멈추지 않는다.

이는 **임시 DB에 저장한 합성 완주 1건의 재생 검증**이다. 사용자의 실주행 개인 기록이나 운영 서버 데이터를 조회·재생한 것은 아니다. 실제 기기·운영 배포 인수는 별도로 남는다.

## 저장된 기록 → API 응답 → 앱 재생 증거

별도 Testcontainers PostGIS DB에서 기존 코스 준비/시작 → 원본 업로드 → 서버 완주 판정/저장 → 본인 재생 API를 실행했다. 30초 정지 샘플의 코스 총 소요는 230,000ms, 수동 정지를 제외한 시간은 200,000ms이고 GPS 공백은 0ms다.

실제 API 응답은 BackEnd/build/ghost-playback-check/own-completed-record.json에 내보냈고, 앱 도구로 그 JSON을 그대로 읽었다.

| 경과시간 | 앱 재생 상태 | 코스상 위치 |
|---|---|---|
| 0ms | tracked | 0m |
| 45,000ms | paused | 약 200m |
| 120,000ms | tracked | 약 450m |
| 230,000ms | finished | 약 1,000m |

반복 조회 뒤 원본 입력·저장 결과·목록 요약이 바뀌지 않는 것도 DB에서 확인했다. 타인/없는/삭제 기록은 404, 원본이나 스냅샷이 없으면 재생 불가 사유를 제공한다.

## 남은 작업과 별도 확인

- 내 최고/최근/과거 후보 조회와 선택 화면, 타인 공개 후보, 시작 시 상대 고정, 승패 저장, 60초 재개, 실제 지도/결과 연결은 다음 구현 단위다. 이번에 MVP 전체를 완료한 것으로 표시하지 않는다.
- 공개 제공 전 ranking/member 계약, 공동 리뷰, Swagger 반영과 실제 앱 연동, 실제 사용자 기록·Android 실기기 검증이 필요하다.
- 첫 구현 검증에서 관찰한 공동 측정기의 GAP null 처리 문제는 후속 작업으로 수정했다. PACE_V2/V3의 첫 GPS 전·수동 정지 중·연속 GAP을 공통 샘플로 재현하고 서버 nullable 처리만 수정했다. 최신 검증은 서버 150개·앱 293개 통과이며 기존 측정 규칙은 유지했다. 상세 변경과 담당자 승인 전 리뷰 항목은 [GPS 공백 수정과 F5·F6 공동 리뷰](<GPS 공백 null 처리 수정과 F5·F6 공동 리뷰 - 2026-10-26.md>)에 있다.
- 첫 샘플의 USER 종료를 기존 계약인 '일시정지 뒤 종료'로 바로잡아 저장 통합 검증했다. 정책에 맞지 않는 샘플을 통과시키려고 기존 업로드/측정 규칙을 완화하지 않았다.
