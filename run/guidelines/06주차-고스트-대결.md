# 6주차 — 고스트 대결

[전체 안내](README.md) · 이전: [5주차](05주차-완주와-리뷰-자격.md) · 다음: [7주차](07주차-통합과-실기기-검증.md)

**목표:** 동일 코스의 과거 완주 기록을 총 소요시간으로 재생하고, 서버의 승리·패배·무승부·무효 결과를 표시한다.

## 1. 진입 조건과 재생 계약

5주차의 코스 완주·시간·구간 종료 결과가 통과해야 한다. RankingApi 공개 후보·실제 순위·허용 상태와 member 공개 상태 계약을 확인한다.

ghost_pause_and_finish 자료에는 elapsedMs, routeSegmentIndex, coursePositionM, pauseState, 품질 구간, 코스 총 소요시간·동일 정수 초 변환 버전을 포함한다. 코스 ID가 같아도 시간 기준/자료 버전이 다르면 그대로 비교하지 않는다.

## 2. 1일차 — 후보 선택과 시작 검증

1. B는 내 최고·최근·과거 완주 기록을 run 내부에서 조회한다. 공개 후보는 RankingApi 공개 계약으로 받는다. 최고와 최근이 같은 기록일 때 중복·표시 규칙을 합의한다.
2. 같은 코스·서버 완주·기록 존재·선택 가능한 공개 범위를 검증한다. 개인 미완주나 삭제 기록을 후보에 넣지 않는다.
3. A는 C1/C2/C9/C10 선택 흐름을 연결하고 내 기록 선택 진입과 공개 랭킹 선택 진입을 구분한다.
4. 후보 선택 때뿐 아니라 실제 시작 때 사용 자격을 확인한다. 선택 후 삭제·공개 해제는 신규 시작을 제한한다.
5. 코스·고스트 재생 스냅샷을 내려받아 기기에 저장한다. 다운로드 불완전 상태는 시작 완료로 취급하지 않는다.
6. 진행 중 상대는 고정하고, 이후 원본 삭제가 시작 스냅샷이나 종료 결과 비교를 삭제하지 않게 한다.

## 3. 2일차 — 재생 엔진 먼저 구현

1. A는 화면 타이머가 아니라 RunRecorder의 경과 총 소요시간을 GhostPlayback에 전달한다.
2. elapsedMs의 자료를 찾고 해당 구간의 위치·정지 상태를 재생한다. 러너가 PAUSED여도 고스트의 총 시간은 진행한다.
3. 고스트 기록의 정지 구간에서는 고스트 위치가 멈춘다. 정지 시간을 잘라내 빠르게 도착시키지 않는다.
4. GPS 공백·모호한 경로 대응은 품질 상태로 표시한다. 확인되지 않은 이동을 보간해 격차를 만들지 않는다.
5. 앱 복구 시 현재 총 소요시간의 위치에서 재생한다. 처음부터 재생하거나 지나간 안내를 한꺼번에 내보내지 않는다.
6. 같은 코스상 위치에 여러 번 도달하는 경우의 시간 차이·고스트가 아직 도달하지 않은 위치의 표현을 계약에 남긴다.

샘플을 실제 속도로 재생하기 전 고정 시간 입력으로 위치·정지·도착 상태를 자동 검증한다.

## 4. 3일차 — 지도와 격차 표시

1. C4 기본·지도·상세 지표 화면에 고스트와 러너의 코스상 위치를 표시한다.
2. 거리 격차는 같은 총 시간의 코스상 위치 차이다. 총 주행 거리·인정 거리 차이로 대체하지 않는다.
3. 시간 격차는 동일 기준 경로 위치에 도달한 총 소요시간 차이다. 왕복/순환의 구간 index·누적 위치로 구분한다.
4. 앞섬/뒤처짐 부호·단위·표시 반올림을 계약으로 정한다. 대응이 모호하면 —를 표시한다.
5. 고스트 선도착 때 상태만 갱신하고 러너의 도전을 계속한다. 즉시 패배 팝업·자유 전환을 넣지 않는다.

## 5. 4일차 — 서버 결과와 경로 제공

1. B는 완주한 러너와 고스트의 코스 총 소요시간을 동일한 정수 초 규칙으로 비교한다. 짧으면 승리, 길면 패배, 같으면 무승부다.
2. 미완주 구간 마감 시 이미 고스트가 도착했으면 패배, 도착 전이면 무효다. 세션 END 시각이 아니라 도전 마감 시각으로 비교한다.
3. 완료 후 추가 자유 러닝·서버 응답 지연을 승패 시간에 더하지 않는다.
4. ghost_matches에 결과·사유·사용한 시간/정책 버전·스냅샷을 보존한다.
5. A는 D2에 판정 대기와 서버 결과를 표시하고 세션 종료 후 결과를 안내한다. 승패 음성은 추가하지 않는다.
6. B는 GET records/{id}/course-source로 세션 전체 실제 경로·단절 구간·고도/등록 여부·품질을 제공한다. 코스 인정 경로로 바꾸지 않는다.
7. course로 전달하는 이벤트/API 계약을 담당과 확정한다. 최종 생성 품질·최소 거리·유사도·한도 검증은 course의 책임이다.

## 6. 5일차 — 재생과 판정을 함께 검증

| 조건 | 기대 결과 |
| --- | --- |
| 러너만 정지 | 러너 거리/달린시간 정지, 고스트 시간 진행 |
| 고스트 기록에 정지 | 그 시간만 고스트 위치 정지 |
| 러너 정지 중 고스트 도착 | 도착 시점은 지연되지 않음, 도전은 계속 |
| 같은 정수 초의 서로 다른 원본 ms | 합의한 변환 후 무승부 |
| 고스트 도착 전 미완주 마감 | 무효 |
| 도착 후 미완주 마감 | 패배 |
| 마감 후 자유 러닝 중 상대 도착 | 마감 시점 결과 유지 |
| 선택 후·시작 전 공개 해제 | 시작 제한 |
| 시작 후 상대 삭제/비공개 | 스냅샷 재생·개인 결과 비교 보존 |
| 왕복 같은 좌표·GPS 공백 | 구간으로 구분, 모호하면 격차 — |
| 실제 경로 코스 등록 진입 | 전체 정상 경로·단절 정보가 전달됨 |

[검증 기록](검증-기록-템플릿.md)에 고정 시간별 위치, 마감/상대 도착 시각, 원본·정수 초, 결과 화면을 함께 남긴다.

## 7. 완료 기준과 다음 단계

- [ ] 내 최고·최근·과거 완주와 공개 후보 선택·사용 허용 검증이 연결된다.
- [ ] 사전 다운로드·시작 스냅샷과 상대 고정이 동작한다.
- [ ] 총 시간·양쪽 정지·선도착·공백 재생이 자동/실기기로 검증된다.
- [ ] 코스상 거리/시간 격차 및 계산 불가 표시가 일관된다.
- [ ] 승리·패배·무승부·무효와 마감 후 시간 고정이 서버 결과와 일치한다.
- [ ] 실제 주행 경로 전달 계약·결과 비교 보관 범위가 정해져 있다.

RankingApi가 스텁이면 재생·판정 완료와 실제 후보 연동 미완료를 구분한다. 시간축이 어긋나면 1주차 시간 규격과 5주차 코스 완료 시점을 먼저 점검한다. 7주차에 실제 인증·코스·랭킹·리뷰를 함께 검증한다.
