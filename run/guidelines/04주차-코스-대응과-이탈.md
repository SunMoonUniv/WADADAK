# 4주차 — 코스 대응과 이탈

[전체 안내](README.md) · 이전: [3주차](03주차-복구와-기록.md) · 다음: [5주차](05주차-완주와-리뷰-자격.md)

**목표:** 코스 시작 스냅샷·활성 수를 연결하고, GPS를 실제 코스 구간에 대응시켜 인정 범위를 계산한다. 앱은 품질·진행 위치·이탈을 안내한다.

## 1. 진입 조건과 테스트 자료

자유 러닝 원본 저장·복구가 통과해야 한다. CourseApi의 경로 좌표 순서·거리·상태·버전 계약과 코스 시작/종료 신호 멱등 규칙을 확인한다.

직선·왕복·순환·교차·지름길·평행 도로 샘플을 만든다. 기준 경로 각 구간의 index·누적 거리, GPS 순번, 정지/GAP, 예상 인정 범위를 포함한다. 거리·반경·품질 수치는 실험 설정으로 버전 관리한다.

## 2. 1일차 — 준비·시작·활성 수

1. B는 쓰기 트랜잭션 밖에서 CourseApi를 조회하고 공개 상태·경로·거리·버전의 스냅샷을 run에 저장한다. 다른 모듈 테이블/Entity를 직접 조회하지 않는다.
2. A는 C6/C8 준비·코스 선택·H1 카운트다운을 연결하고 스냅샷을 기기에 저장한다.
3. 카운트다운 종료의 course-start 신호에서 시작 자격을 재확인한다. 응답 유실은 동일 요청/상태 확인으로 복구한다. 미확인 상태를 새 세션으로 우회하지 않는다.
4. 실제 START 시각·streamSeq와 서버 시작 신호를 대응시키는 계약을 적용한다. 시작 실패를 정상 RUNNING으로 표시하지 않는다.
5. B는 실제 시작을 한 번만 반영하고 CourseRunStartedEvent 및 활성 수 변경 이벤트를 저장한다. 준비만으로 도전 수를 올리지 않는다.
6. 같은 사용자의 동시 활성 세션 처리, 시작 확인 실패·방치 세션 처리 계약을 course와 기록한다. 완료 신호 없이 활성 수가 영구 증가하지 않도록 설계한다.

시작 이후 측정은 다운로드한 스냅샷으로 진행한다. 오프라인 코스 신규 시작은 허용하지 않는다.

## 3. 2일차 — 거리 모델과 직선 대응

1. 총 주행 거리, 코스 인정 거리, 코스상 위치를 별도 값으로 만든다.
2. B는 순서 있는 기준 경로를 구간 index·구간 내 위치·누적 위치로 표현한다. SRID 4326 좌표의 도 단위 길이를 m로 취급하지 않는다.
3. 정상 GPS를 후보 구간에 투영하고 전후 이력·방향·연속성·품질로 대응을 선택한다. 가장 가까운 선 또는 가장 먼 위치만 고르지 않는다.
4. 연속 투영 사이 실제 주행이 확인된 범위만 인정한다. GPS 이동 거리 자체를 코스 거리로 합산하지 않는다.
5. recognized_intervals를 구간별 합집합으로 관리한다. 같은 구간 반복은 한 번, 왕복의 가는/오는 구간은 별도 index로 인정한다.
6. 직선 샘플로 기본값을 검증하고 인덱스/거리 단위 오류부터 수정한다.

## 4. 3일차 — 모호한 경로·공백 대응

1. 왕복에서는 같은 좌표의 가는/오는 구간을 이전 진행 이력으로 구분한다.
2. 순환은 시작=도착 좌표여도 진행 이력 없이 끝에 도달했다고 처리하지 않는다.
3. 교차·평행 도로에서 대응을 특정하지 못하면 품질상 판단 보류로 남긴다. 최고 진행 위치를 택해 완주 거리를 늘리지 않는다.
4. 지름길 복귀 시 복귀 후 실제 구간만 추가한다. 건너뛴 구간을 자동 인정하지 않는다.
5. PAUSE/GAP/복구 경계를 가로질러 인정하지 않는다. 원본·정제 경로·지도 경로를 분리한다.
6. 전송 순번 누락과 GPS의 근본적 모호함을 구분한다. 전자는 자료 보완, 후자는 품질 결과/정책 처리 대상이며 무한 재업로드로 해결하지 않는다.

예상 인정 구간 목록과 계산 결과를 비교한다. “맞는 총합”만 확인하지 말고 잘못된 구간을 서로 상쇄해 합이 맞는 경우도 잡는다.

## 5. 4일차 — 앱 지도·이탈 안내

1. A는 코스 기준선·실제 주행선·현재 위치를 지도 래퍼로 표시한다. 코스 km 표지는 기준 경로 누적 거리로 고정하며 판정용 체크포인트로 사용하지 않는다.
2. 기기 RouteGuidance는 표시용 코스상 위치·이탈 후보/확정·복귀·판단 보류를 계산한다. 서버의 최종 인정 거리·완주 자격으로 취급하지 않는다.
3. 이탈·복귀의 거리/시간/확인 횟수는 조정 가능한 실험 설정으로 둔다. 문서의 30m/20m 등 테스트 수치를 완주 반경으로 재사용하지 않는다.
4. GPS 불량은 판단·반복 안내를 보류하고 지속 시간 누적을 초기화한다. 일시정지는 판단/음성을 중단하고 재개 후 다시 확인한다.
5. 팝업·음성·진동과 “확인/다시 표시하지 않음”을 연결한다. 안내 억제가 측정·서버 판정·MY 거리/시간 음성을 끄지 않게 한다.
6. 후보·확정 음성 및 반복 시점은 정책을 따른다. 30초 안내 반복과 30초 자동 전환 타이머는 별도로 둔다. 최종 구간 종료는 5주차에서 연결한다.

## 6. 5일차 — 재생·실기기 검증

| 경로/상황 | 검사 |
| --- | --- |
| 직선 | 정상 방향·거리 단위·인정 범위 |
| 왕복 | 동일 좌표의 서로 다른 구간, 실제 순서 |
| 순환 | 출발 즉시 도착 판정 금지 |
| 교차 | 지나간 한 지점으로 주변 구간 전체 인정 금지 |
| 지름길·후반 복귀 | 현재 위치와 인정 거리 분리 |
| 평행 도로 | 모호한 대응을 확정 인정으로 바꾸지 않음 |
| 반복·정지·GAP | 합집합·경계 처리 |
| 시작 신호 재시도 | 시작/활성 수 중복 없음 |

B는 실제 PostGIS 환경에서 같은 자료 재생 결과가 결정적인지 확인한다. A는 직선·왕복 등 안전한 실기기 경로에서 안내/품질 상태를 확인하고 배터리·위치 환경을 기록한다.

## 7. 완료 기준과 실패 대응

- [ ] 실제 시작 스냅샷·오프라인 시작 제한·멱등 시작 신호가 연결된다.
- [ ] 총 거리·인정 거리·코스상 위치를 구분해 저장·표시한다.
- [ ] 직선·왕복·순환·교차·지름길·평행 도로 자료의 구간별 결과를 검토했다.
- [ ] 반복·정지·GPS 공백으로 인정 범위가 부풀지 않는다.
- [ ] 품질 보류·이탈/복귀·안내 억제 동작이 서로 구분된다.
- [ ] 실제 DB 검증·실기기 안내 증거와 파라미터 버전이 있다.

잘못된 인정이 나오면 허용 반경을 무작정 키우지 말고 구간 선택·시간 경계·단위를 재현 자료로 확인한다. 인정 범위가 안정된 뒤 5주차의 완주·리뷰 결과를 연결한다.
