# 기록 목록 경로 썸네일 — 2026-10-29

`GET /api/v1/runs/records`의 각 `data.content` 항목에 선택 필드 `routeThumbnail`을 추가한다. B6(내 기록에서 코스 등록) 등 목록 카드는 이 값으로 경로를 그리고, 경로 표시를 위해 카드마다 `course-source`를 호출하지 않는다.

```json
{
  "routeThumbnail": {
    "version": "RUN_ROUTE_THUMBNAIL_V1",
    "segments": [
      [{"lat": 36.0, "lng": 127.0}, {"lat": 36.0001, "lng": 127.0}],
      [{"lat": 36.1, "lng": 127.0}, {"lat": 36.1001, "lng": 127.0}]
    ]
  }
}
```

- `segments`의 각 배열을 별도 선으로 그린다. GPS 공백·튐·일시정지로 나뉜 배열 사이를 연결하지 않는다. 모든 배열에 공통 경계·축척을 사용한다.
- 새 기록 처리에서 이미 계산한 `calculation.segments`로 한 번 생성해 `summary_json`에만 저장한다. 원본 GPS 추가 조회, DB 공간 연산, 다른 모듈 호출은 없다. 재업로드·처리 재시도에서도 저장된 값을 유지한다.
- 각 구간의 첫 점과 끝 점을 보존하고, 미터 좌표로 계산한 굴곡이 큰 지점부터 남기는 Douglas-Peucker 방식으로 줄인다. 8m 이하 굴곡은 생략하며 모든 구간을 합쳐 최대 128점을 저장한다. 점 수 상한에 도달하면 8m보다 큰 오차가 남을 수 있어 썸네일 표시 전용이다. 좌표는 선택된 원래 좌표 그대로이며 정확도·고도·시간은 넣지 않는다.
- 비어 있는 구간은 생략한다. 한 점짜리 구간은 한 점으로 보존한다. 모든 구간의 끝점만으로 128점을 넘으면 일부 구간을 버리거나 연결하지 않고 `segments: []`를 저장한다. 이 경우 카드는 기본 이미지를 표시한다.
- 기존 기록은 필드 누락 또는 `null`을 허용한다. `null`, 빈 배열 또는 선을 그릴 수 없는 데이터이면 카드의 기존 기본 이미지를 표시한다. 목록 조회 중 원본·상세 경로 재계산이나 자동 채우기는 하지 않는다. 기존 기록을 일괄 채우는 작업은 포함하지 않는다.
- GPS 단절 판단(`saveGpsGap`)은 저장된 요약에서 `gpsGap`만 바꾸며 썸네일의 버전·좌표·구간을 보존한다. 과거 기록의 `null`도 유지한다.
- 목록은 계속 `summary_json`만 조회한다. 원본 GPS·`result_json`을 읽지 않으며 목록 조회의 쓰기 동작도 없다. 기존 회원별 접근 제한과 커서 페이지 계약을 따른다.
- 코스 등록 요청에는 기존 `GET /api/v1/runs/records/{id}/course-source`의 경로를 사용한다. 썸네일로 거리·GPS 품질·코스 등록 가능 여부를 판단하지 않는다. 상세 경로·거리·시간·랩·랭킹·이벤트는 그대로 유지한다.

기존 JSON에 선택 필드를 추가하므로 DB 컬럼·인덱스 변경은 필요 없다. B6 화면 구현은 이 변경에 포함하지 않으며, 화면 담당자는 위 계약으로 별도 선 그리기를 연결할 수 있다.
