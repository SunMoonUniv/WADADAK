# 코스 러닝 서버 연결 (F6 B단계)

작성: 2026-10-20 · 2번 문석용 → 1번 김효성 · 근거: 정책 D-08(4.1), 공통 7, D-14, RUN-04, 5.3 · 개발 정책 흐름도(코스 러닝 시작부터 랭킹 반영까지)

코스 러닝을 서버가 알게 해서 **업로드된 코스 기록마다 서버가 완주를 판정하고 이벤트 코스 칸을 채운다.** 이걸로 course(유지 기간 연장·완주 수·평균 페이스·도전 수·현재 러너 수), ranking(코스 랭킹), review(리뷰 자격)가 실제 데이터로 움직인다. 자유 러닝 흐름은 바뀌지 않는다.

## 1. 흐름

```
① C6 "이 코스로 달리기"   PUT  /api/v1/runs/sessions/{id}/course        {courseId}
     → 코스 공개 여부·경로·거리 확인(CourseApi), 판정용 경로 스냅샷 저장 → 스냅샷 응답
② 카운트다운 끝          POST /api/v1/runs/sessions/{id}/course/start  {startedAt}
     → CourseRunStartedEvent(도전 수) + CourseActiveRunnersChangedEvent(+1)
③ 구간 종료(온라인이면)   POST /api/v1/runs/sessions/{id}/course/segment-end
     → 현재 러너 수 −1
④ 러닝 종료 → 업로드     PUT  /api/v1/runs/sessions/{id}  {startedAt, mode}  → 기존 upload (코스 여부는 서버의 코스 시도로 정함)
     → 다 도착하면(③이 없었으면) 현재 러너 수 −1
     → 처리: 자유 러닝 계산(그대로) + 코스 판정 → Result.course, RunSessionEndedEvent 코스 칸
⑤ ③④ 없이 시작 후 3시간 → 정기 작업이 현재 러너 수 −1 (앱 강제 종료·방치)
⑥ 기록 삭제 → RunRecordDeletedEvent 코스 칸(startedAt = ②의 이벤트 시각)
```

- ①·②가 실패하면 앱은 "연결 실패"를 안내하고 시작하지 않는다(D-08). 시작 뒤에는 통신이 끊겨도 계속 달린다
- 판정 경계는 기록의 `SEGMENT_END` 입력이다. ③ 신호는 현재 러너 수에만 쓰고 판정에는 쓰지 않는다

## 2. API

| API | 요청 | 응답 | 재시도·오류 |
| --- | --- | --- | --- |
| `PUT /sessions/{id}/course` | `{"courseId": UUID}` | `CourseSnapshot` `{sessionId, courseId, name, route[{lat,lng}], totalDistanceMeters, version}` | 같은 세션·코스면 처음 스냅샷 그대로. 다른 코스 `RUN-003`(CONFLICT), 이미 자유 러닝으로 준비된 세션 `RUN-003`(CONFLICT), 없는 코스 `COURSE-001`, 비공개·삭제 `COURSE-002` |
| `POST /sessions/{id}/course/start` | `{"startedAt": Instant}` (측정 시작 시각) | 없음 | 같은 startedAt이면 한 번만 반영. 다른 startedAt `RUN-003`(CONFLICT), 준비 안 함 `RUN-002`(NOT_FOUND), 미래 5분 초과 `RUN-001`(INVALID) |
| `POST /sessions/{id}/course/segment-end` | 없음 | 없음 | 항상 성공. 자유 러닝·모르는 세션·이미 빠진 세션은 무시 |
| `PUT /sessions/{id}` (기존) | `{"startedAt", "mode": "FREE" \| "COURSE"}` | 기존 Status | **코스 러닝인지는 서버에 남은 코스 시도로 정한다.** 앱이 재실행돼 코스 정보를 잃고 `FREE`로 보내도 코스 기록으로 판정한다. 코스 시도가 있으면 ②와 같은 startedAt만(다르면·시작 신호 전 `RUN-003`(CONFLICT)), 코스 시도 없는 세션을 `COURSE`로 `RUN-002`(NOT_FOUND) |
| `GET /records/{id}` (기존) | | `Result`에 선택 `course` 추가 | 아래 3장 |

## 3. `Result.course` — 서버 코스 판정 (결과 화면 D1·D1-1용)

코스 러닝 기록에만 있다. 자유 러닝은 null.

| 필드 | 의미 |
| --- | --- |
| `courseId`, `courseVersion` | 달린 코스와 그때 버전 |
| `courseDistanceMeters` | 코스 전체 거리(코스 등록 값) |
| `completed` | 서버 완주 |
| `reason` | `COMPLETED` · `START_NOT_CONFIRMED` · `FINISH_NOT_REACHED` · `DISTANCE_SHORT` |
| `recognizedDistanceMeters`, `progressPercent` | 코스 인정 거리, 진행도(0~100) |
| `completedAt` | 완주 시각(미완주 null) |
| `courseElapsedSeconds`, `courseMovingSeconds` | 코스 총 소요·달린 시간(정수 초, `floor(ms/1000)` 잠정) |
| `reviewEligible` | 리뷰 자격 |

`RecordSummary`(목록)에는 아직 넣지 않았다. MY 기록 목록에서 완주 표시가 필요하면 말해 달라.

## 5. 앱에서 할 일 (C단계)

**최소 연결은 반영함(2026-10-20, 아래 ✅).** 기기 SQLite·`RunSyncWorker`는 바꾸지 않았다(업로드 준비는 `FREE` 그대로, 서버가 코스 시도로 판정).

1. ✅ 코스 상세(B1·G3) `이 코스로 달리기` → 코스를 고르고 달리기 탭으로(`course_run_entry.dart`). 준비 화면에 `코스 러닝` 탭과 코스 이름. `자유 러닝` 탭을 누르면 해제
2. ✅ 시작: ① 준비(카운트다운 전) → 카운트다운 → ② 시작 신호 성공 뒤 측정 시작. 기록과 같은 세션 ID·startedAt을 쓴다. 인터넷이 안 되면 "연결 실패", 비공개 코스면 서버 문구로 안내하고 시작하지 않는다(`RunController.prepareStart`)
3. ✅ 결과 화면: `Result.course`로 코스 완주·미완주 이유·진행도·인정 거리·리뷰 자격. 서버 판정 전은 "판정 대기"(D-14)
4. ✅ 출발점 안내(RCR-01, 2026-10-21): C6 시작 → ① 준비 → 새 화면 없이 러닝 화면의 측정 전(준비) 상태(`course_start_view.dart`). 어두운 지도에 코스 경로(스냅샷)·출발점·내 위치·내 위치~출발점 점선(`MapLineStyle.guide`)·남은 거리. 출발점 20m(`CourseStart.radiusM`, 서버 경로 일치 오차 이하) 안에서만 시작 버튼이 켜지고 1초 누르기 → H1(머리말 코스 이름) → ② 시작 신호 → 측정. 취소하면 C6로. 측정 전 위치는 기록 중 알림 없이 따로 받는다
   - C6 `코스 러닝 시작`은 일단 Figma대로 **길게 누르기 유지**. RCR-01은 "준비 화면의 시작은 누르면 시작점 지도로 넘어간다"(짧게 누르기)라 정책·디자인 중 하나로 맞춰야 한다. 지금 흐름이면 C6에서 한 번, 측정 전 화면에서 한 번 길게 누른다
   - 측정 전 지도에는 km 표지를 넣지 않았다(준비 응답에 없음)
5. ✅ 달리는 중 코스 화면(C4 코스·C4-1, 2026-10-21): 서버 판정 엔진(RouteGeometry·CourseTracker·RecognizedDistance)을 Dart로 옮긴 `course_tracker.dart`가 GPS마다 코스상 위치·인정 거리를 따라간다(안내용, 완주 판정 아님 RCR-07). 머리말 코스 이름, 지도에 코스 경로(주행선 아래)·코스 출발점·코스 1km 표지, 남은 거리(전체 − 코스상 위치)·코스 진행 %(인정 거리 ÷ 전체)·"N km 지점까지 xxx m"·총 거리
   - 서버 판정 엔진을 고치면 `course_tracker.dart`도 같이 고친다(기준값 20m·12m/s·10초 포함). 서버 테스트와 같은 사례를 `test/run/course_tracker_test.dart`로 확인
   - 경로 기기 저장은 하지 않는다: 앱이 꺼졌다 켜지면 1번 복구가 그 러닝을 `INTERRUPTED`로 끝내므로(이어 달리기 없음) 되살릴 화면이 없다. 이어 달리기가 생기면(ERR-07 확정) 그때 저장
   - 뺀 것: Figma 라임 "목표 페이스" 카드(정책에 없음, 최고 기록·고스트 필요), 지도 위 "N km 지점까지" 덮개(지도 아래 문구로 대신)
6. 남음: 이탈 안내(`RouteGuidance`: 경로까지 거리는 추적기의 d로 구한다)
7. 남음: 경로 끝 도착·코스만 종료 → 기록에 `SEGMENT_END`(`ROUTE_END`/`COURSE_ONLY`) + 온라인이면 ③. 지금은 `END`가 경계
