# F6 코스 판정 기대값

작성일: 2026-10-12 · 담당: 2번 문석용 · 상태: 초안(1번 김효성 리뷰 전)

서버 코스 판정 엔진의 테스트 기대값이다. 판정 코드로 다시 계산하지 않고 이 표의 값을 그대로 쓴다. 1번과 공통 규격을 맞출 때 샘플로도 쓴다.

근거: [정책 문서](../정책%20문서.md) 공통 2·5, 제3부 4장(선투영·구간 인정)·5.3(완주)·5.5(리뷰)·7.3(이탈 후 기록), 제4부 3(검증 시나리오). [달리기 개발 아키텍처](달리기%20개발%20아키텍처%20-%202026-10-06.md) 8장.

## 1. 판정 규칙

| 항목 | 규칙 |
| --- | --- |
| 코스 인정 거리 | 정방향으로 실제 주행이 확인된 코스 구간 길이의 합. 같은 구간은 한 번만 |
| 진행도 | 인정 거리 ÷ 코스 전체 거리 × 100. 100% 초과 없음 |
| 완주 | 출발 확인 **AND** 경로 끝 도달 **AND** 인정 거리 ≥ 전체 × 0.95 (경계 포함) |
| 리뷰 자격 | 인정 거리 ≥ max(1,000m, 전체 × 0.2) (경계 포함). 완주와 독립 |
| 판정 범위 | 앱의 코스 구간 종료(SEGMENT_END) 이전 데이터만 |
| 완주 시점 | 세 조건을 처음 함께 충족한 표본 시각. 코스 시간·거리는 이 시점 값으로 고정 |

인정하지 않는 것: 코스 밖 이동, 역방향 주행, 일시정지 중 이동, GPS 공백 사이 직선 연결, 코스를 한 점에서 가로지른 것, 구간 종료 이후 주행.

## 2. 표기

- `s`: 코스상 위치(m). 출발점 0, 도착점 = 전체 거리
- 경로 위: 경로선까지 거리 ≤ 3m. 코스 밖: ≥ 100m
  - 출발·도착 반경과 경로 일치 오차는 아직 정하지 않았다. 샘플은 그 값이 무엇이든 결과가 같게 설계했다.
- 이벤트: `START` `PAUSE` `RESUME` `GAP`(GPS 공백) `SEGMENT_END`(앱 코스 구간 종료, 사유: 경로 끝 도착 / 코스만 종료) `END`(세션 종료)
- 이탈이 오래 지속돼도 자동 구간 종료는 없다(정책 7.3, 4.4)
- "a→b": 경로 위를 s=a에서 s=b까지 정방향으로 촘촘한 표본으로 주행
- 출발 확인: 첫 표본이 s=0 근처. 끝 도달: 표본이 s=전체 거리 근처

## 9. 아직 정할 값

이 표는 아래 값과 무관하게 성립하도록 만들었다. 값이 정해지면 경계 사례를 추가한다.

- 출발 반경, 도착 반경, 경로 일치 허용 오차 (실기기 주행 검증)
- 보류의 기준: 몇 개 표본, 몇 m까지 구간을 특정하지 못하면 보류할지
- 평행한 옆길과 코스를 구분할 수 없는 경우 (오차 확정 후 추가)
- 정수 초 변환 규칙 (ranking 담당과 계약 PR에서 확정)
