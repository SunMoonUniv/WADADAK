## 코스러닝 담당 화면이 준비된 뒤 연결할 곳

이번에는 기존 라우터·MY·F6 준비/재생/지도·기존 RunRecorder/Controller/SyncWorker·시계·추적기·위치·core 파일을 수정하지 않았다. 따라서 현재 앱 메뉴에서 새 선택 컴포넌트로 들어가는 경로도 아직 등록하지 않았다.

1. 기존 인증된 RunApiClient로 OwnGhostApi를 만들고 현재 회원과 코스 준비 응답의 courseId/version으로 OwnGhostController를 생성해 load한다. 현재 F6 앱 CourseSnapshot은 ID/version을 보존하지 않으므로 담당자가 공유 모델을 확장하거나 원래 준비 응답에서 F9 컨텍스트를 전달하는 방식을 공동 리뷰한다.
2. OwnGhostSelectionView에 controller/courseName/onBack/onPrepared를 전달한다. 재생 가능한 기록을 고른 뒤 CTA를 누르면 PreparedOwnGhost를 받는다. 계정·코스 변경은 changeContext 또는 기존 controller dispose 후 새 생성으로 처리한다. 화면 소유자가 controller의 수명을 관리한다.
3. F6 화면이 준비되면 이 준비 자료와 기존 코스 경로를 전달하는 어댑터를 연결한다. 지도·타이머·측정기를 F9 전용으로 복제하지 않는다.
4. 실제 대결 시작 구현에서 서버의 코스/상대 재검증과 시작 승인·상대 고정·내구성 저장을 먼저 완료한다. 메모리 prepared나 onPrepared 콜백만으로 기존 F6 start를 호출해 고스트가 시작된 것으로 처리하지 않는다.
5. 이후 동일 시계의 지도 재생/격차, 60초 재개, 결과/승패·삭제/30일 보존을 계획대로 구현한다. 공개 상대는 ranking/member 계약을 거쳐 별도로 추가한다.

## 공동 리뷰 목록

- F5/F6: RunContracts에 추가한 후보/요약/페이지 DTO, 저장된 코스 값 사용·버전 분리, 목록/선택 조회의 결과·원본 불변. 이전 GAP null 수정과 앞선 CourseJudge 분석 결과 노출은 기존 리뷰 문서와 함께 확인한다.
- run 담당: 후보 SQL은 run 스키마에만 접근한다. 실제 시작 시 코스 존속 검증을 대체하지 않으며, 대량 기록의 text JSON 투영 비용·필요한 후속 인덱스는 별도 검토한다.
- 앱 공통: 기존 인증된 Dio/runOwner 재사용, 계정 변경 시 준비 상태 폐기와 화면 수명 인계. core/인증 구현을 수정하지 않았다.
- F6 화면 담당: 코스 ID/version 전달과 onPrepared 인계, 재생/지도 연결 시점. 담당 화면 작업을 덮어쓰지 않았다.
- MY·ranking·member·이벤트·DB 스키마 변경 없음. 담당자에게 메시지를 보내거나 리뷰 승인을 받은 것으로 표시하지 않는다.
