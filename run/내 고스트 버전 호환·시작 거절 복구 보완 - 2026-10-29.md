# 내 고스트 버전 호환·시작 거절 복구 보완 · 2026-10-29

**2026-10-30 후속 구현:** 공개 러너 전체 선택 C10과 다중 후보 조회·기간·정렬·더 보기를 추가했다. 아래 당시 후속 목록의 C10 항목은 [새 구현 계약](<공개 고스트 다중 선택과 준비 지도 개선 - 2026-10-30.md>)으로 대체한다. 기존 재생·시작 승인·개인정보·보존 규칙은 유지한다.

정책 공통 6·달리기 9의 같은 코스·방향, 원본 불변, 시작 전 재검증, 승인 후 상대 고정과 60초 재개를 유지하는 보완이다. 별도 자료 만료 기간·완주 기준·자유 기록 최소 거리를 추가하지 않는다.

## 내 코스 기록의 버전 호환

- 코스 엔티티 버전은 유지 기간·이름 변경으로도 증가한다. 과거 완주를 숫자 버전 차이만으로 제외하지 않는다. 원본은 저장 당시 버전·계산 방식으로 재현하고 현재 코스와 ID·순서 있는 전체 좌표·정수 거리가 정확히 같으며 미래 버전이 아니어야 한다. 경로 조각·경로 변경·역방향·거리 변경은 허용하지 않는다.
- 후보는 run의 저장 결과·course_attempts와 현재 CourseApi 스냅샷을 읽는다. 과거 버전의 원본 스냅샷이 없거나 일치하지 않으면 제외한다. 같은 조건으로 전체 요약·최고·페이지를 계산하며 목록 조회에서 GPS를 재생하지 않는다. 준비 버전이 이미 달라졌으면 RUN-003으로 다시 준비하게 한다.
- `GET /api/v1/runs/records/{id}/ghost-playback`에 선택 쌍 `courseId`·`courseVersion`을 추가한다. 둘 다 생략하면 기존 원본 버전 응답이다. 둘 다 전달하면 본인 원본을 검증한 뒤 호환되는 재생의 기준 버전만 현재 준비 버전으로 맞춘다. 하나만 전달하면 RUN-001이다. 앱의 내 코스 선택은 이 쌍을 전달한다.
- 후보·선택 재생·시작 승인에서 현재 준비 버전을 사용하지만 원본 JSON·등록 시각·계산 버전은 수정하지 않는다. 승인 DB의 기존 `source_course_version`은 내/공개 원본의 실제 버전을 보존한다. 시작 당시 현재 코스와 준비 스냅샷 검증은 계속 엄격하며, CourseApi 재검증은 쓰기 트랜잭션 밖이다. 새 DB 이관은 없다.

## 확정 거절 뒤 재선택

1. POST 전에 같은 계정·세션 ID의 시작 요청을 기기에 보존한다.
2. POST의 명시적 거절은 RUN-001/400, RUN-002/404, RUN-003/409, RUN-004/409, COURSE-001/404, COURSE-002/409 쌍으로 제한한다. 같은 ID의 GET으로 저장 승인을 다시 확인한다.
3. GET에 승인이 있으면 기존 대결로 복구한다. GET이 RUN-002/404이고 계정이 같을 때만 기존 삭제 예약 기능으로 요청 ID를 취소한다. 기기 취소 저장이 끝나기 전에는 재선택을 허용하지 않는다. 서버 삭제는 기존 동기화가 재시도하며 늦은 승인·업로드로 같은 ID가 되살아나지 않는다.
4. 선택한 상대·출발점 준비를 지우고 `사용할 수 없는 고스트입니다.` / `다른 기록을 선택해 주세요.` / `확인`을 표시한다. 기존 선택 코스는 유지하고 다른 기록을 고르면 새 대결 ID로 다시 준비한다. 자유 기록·공개 상대도 같은 시작 거절 처리를 사용한다.
5. 네트워크·인증·서버 오류, 승인 조회 실패·불일치는 확정 거절로 보지 않는다. 원장을 유지하고 같은 요청으로 복구한다. GET 404 단독은 취소 근거가 아니다. 기존 부팅·단조 시계와 0~60,000ms 경계는 유지한다.
