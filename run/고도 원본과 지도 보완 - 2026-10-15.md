## 적용 내용

- **정책 문서 RUN-09:** 기본 측정 화면의 큰 지표와 하단 세 영역을 독립적으로 터치 전환한다. 총 소요시간 → 달린시간 → 이동시간 → 거리 → 평균 페이스 → 현재 페이스 → 케이던스 순으로 순환한다. 라벨·값·단위가 함께 바뀌고 미수집 값은 `—`다.
- 초기 배치는 기존과 같이 이동시간 / 거리·평균 페이스·현재 페이스다. 측정값 갱신·정지/재개·좌우 슬라이드 중 선택을 유지하며 새 세션은 초기 배치로 돌아간다. 같은 지표를 여러 영역에서 선택해도 서로 바꾸지 않는다. 선택은 화면 상태이며 기기 설정이나 서버 기록에 저장하지 않는다.
- 지표 터치는 표시 선택만 바꾸고 Recorder·GPS·단조 시계·거리/페이스 계산·랩·센서·음성·동기화에 명령을 보내지 않는다. 기존 지도↔기본↔전체 지표 슬라이드와 정지·재개·종료 버튼을 유지한다.
- **고도 원본:** 최초 위치와 실시간 위치의 `hasAltitude`·`hasAltitudeAccuracy`를 확인해 실제 측정값만 `altitudeM`·`altitudeAccuracyM`으로 보존한다. 실제 0m·음수 고도는 유효하다. 비정상 고도는 정상 수평 위치를 버리지 않고 null로 처리한다. 자동 재개 순간에도 고도 필드를 유지한다.
- 기기 SQLite 원본 JSON → 재시작/복구 → 업로드 DTO → 서버 입력 계약 → `run.inputs.payload`까지 같은 원본을 전달한다. 새 서버는 고도 없는 기존 앱/기록도 처리하며 Java의 기존 생성자 호출도 유지한다. 같은 순번의 고도만 바꾼 재업로드는 기존 충돌 규칙대로 거부한다.
- **지도:** 확인된 주행 경로의 첫 점에 출발, 종료 기록의 마지막 점에 종료 표지를 표시한다. 현재 위치는 기존 공통 지도를 사용한다. GPS 공백·일시정지 경로를 잇지 않고 순환 경로에서도 출발/종료 표지가 겹쳐 가려지지 않게 배치한다.
- 정책 문서·개발 정책 v3·DB 구조·FrontEnd README·과거 개발 계획을 현재 구현/검증 상태와 맞췄다. 최신 다른 영역의 정책·DB 변경은 보존했다.

## 적용과 남은 작업

- SQLite DB는 v3 유지, 서버 테이블도 변경하지 않는다. 원본 JSON 선택 필드 확장이므로 새 Flyway 마이그레이션은 필요 없다. 원본·등록 시각·기존 정책/계산 버전을 소급 변경하지 않는다.
- **서버를 먼저 배포한 뒤 새 앱을 사용한다.** 이전 서버가 미지원 필드를 무시하면 새 고도가 버려질 수 있다. 새 앱에서 이전 서버까지의 무손실 고도 저장을 보장하지 않는다.
- 고도 수집 완료는 누적 상승/고도 차트/course-source 구현 완료가 아니다. 기존 고도 없는 기록을 임의로 채우지 않는다.
- 실제 서버 저장→재조회→삭제와 삼성 Android 30분 이상 실외·화면 꺼짐/절전·거리/케이던스 정확도 인수는 남아 있다. iOS는 Android 우선 출시 이후 별도 단계다.
- 거리 0 기록의 원본 보존/개인 목록 제외, 최근 기록 카드·MY 통계·최고 지표·공유·코스 등록·구간 분석의 기존 범위는 이번 작업으로 바꾸지 않았다. 1km 지도 표지는 새로 추가하지 않았다.
