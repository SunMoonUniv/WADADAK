# 내 고스트 후보·선택 준비 계약 v1 · 2026-10-26

**2026-10-29 보완:** 아래는 최초 구현 기록이다. 현재 내 코스 후보·재생·시작에는 [버전 호환·확정 거절 보완](<내 고스트 버전 호환·시작 거절 복구 보완 - 2026-10-29.md>)을 함께 적용한다. 과거 엔티티 버전이라도 같은 코스 ID·순서 있는 전체 경로·정수 거리를 저장 스냅샷으로 확인하면 포함하고, 후보 DTO와 선택 재생의 기준 버전은 현재 준비 버전으로 맞춘다. 후보 조회는 현재 CourseApi와 run 소유 course_attempts만 읽고 GPS 원본 전체를 읽지 않는다. 원본 결과·경로 버전은 덮어쓰지 않는다. 현재 앱 연결 범위는 2026-10-27 진입 계약을 따른다.

상태: 로컬 구현·검증 계약. 재생 화면과 지도는 코스러닝 담당 화면이 준비된 뒤 연결한다. MY의 내 러닝 기록, F6 화면·측정·시작·복구는 수정하지 않는다.

## 범위와 정렬

같은 코스 ID·순서 있는 전체 경로·거리의 본인 서버 확정 완주 기록을 조회하고, 선택한 한 건의 ghost-playback을 검증해 준비 자료로 전달한다. 과거 버전 호환은 위 2026-10-29 보완을 따른다. 이 문서의 최초 범위에서는 실제 대결 시작 승인·상대 고정·SQLite 보존·60초 재개·승패·공개 상대·재생 지도 연결은 후속이다.

MY는 기존 registeredAt DESC를 유지한다. 고스트 최근/과거는 사용자 확정대로 startedAt DESC다. 늦은 업로드가 최근 순서를 바꾸지 않는다. 최고는 저장된 코스 총 소요 정수 초 ASC, 같은 초는 startedAt DESC·기록 UUID DESC로 안정 정렬한다. 최근도 startedAt 동률은 UUID DESC다. 이 동률 정렬은 랭킹 순위를 새로 판정하지 않는다.

## REST

GET /api/v1/runs/ghost-candidates/own?courseId={uuid}&courseVersion={long}&sort=RECENT|BEST&period=ALL|MONTH|WEEK&size=20&cursor={cursor}

JWT 필수. 소유자는 JWT sub만 사용한다. courseVersion은 코스 준비 스냅샷의 version이다. 음수 버전·잘못된 커서/범위/정렬은 거부한다.

ApiResult<OwnGhostCandidatePage>:
- content: id, courseId, courseVersion, startedAt, completedAt(nullable), registeredAt, courseElapsedSeconds, courseDistanceMeters, averageCadence(nullable).
- nextCursor: 다음 페이지가 있을 때만 전달. 코스·버전·정렬·기간/기간 시작과 마지막 정렬 키에 묶인다. 다른 조건 또는 달라진 주/월 범위에 재사용하면 거부한다.
- summary: count, averageSeconds(nullable), best(nullable, OwnGhostCandidate). 현재 페이지가 아닌 조건에 맞는 전체 완주에서 계산한다. 평균은 코스 총 소요 정수 초의 평균이며 랭킹의 러너별 대표 평균과 다르다.
- 기본 20개·최대 50개. 빈 목록은 content=[]·nextCursor=null·summary={count:0,averageSeconds:null,best:null}.
- 내 기록 기간은 startedAt의 Asia/Seoul 월초/월요일 00:00 이상~다음 기간 시작 미만이다. 공개 랭킹의 registeredAt 기간 규칙은 변경하지 않는다.
- 본인 서버 확정 코스 완주만 조회하며 자유/미완주/처리 중/다른 코스·호환되지 않는 경로 또는 버전/삭제·탈퇴 기록을 제외한다. 후보의 courseVersion은 현재 준비 버전이며 원본 결과의 버전은 그대로 보존한다.
- DB에서 기존 result_json의 필요한 필드를 투영하고, 과거 버전은 run 소유 course_attempts의 경로·거리와 현재 CourseApi 스냅샷을 비교한다. 목록 결과는 페이지 크기+1, 요약은 SQL 집계 및 최고 한 건이다. 원본 GPS 입력·재생 생성기를 목록에서 호출하지 않는다. 타 모듈 스키마 직접 조회, MY 목록·DB 스키마 변경은 없다. 기존 text JSON 투영 방식이므로 대량 기록 쿼리 최적화는 담당 리뷰 시 함께 검토할 수 있다.

요약만으로 재생 적합성을 확정하지 않는다. 선택한 한 건에 GET /api/v1/runs/records/{id}/ghost-playback?courseId={uuid}&courseVersion={현재 준비 버전}을 호출한다. 최고/최근 기록이 재생 불가면 사유를 보여 주며 다른 기록으로 대체하지 않는다. 10초 연결 금지·30초/5%는 기존 계약을 유지한다.

## 앱 준비와 경합

기존 RunApiClient의 Dio·owner 옵션, callApi·인증 인터셉터를 쓰는 F9 어댑터 OwnGhostApi를 추가했다. 새 네트워크/인증 기반·core 변경은 없다.

OwnGhostController는 후보 페이지·기간·선택 중·오류/재시도·재생 불가 사유·PreparedOwnGhost를 관리한다. eligible=true 및 유효한 GHOST_PLAYBACK_V1에 sourceRecordId, course ID/version, 코스 정수 초가 후보와 일치해야 준비 완료다. 실제 API 응답 전체는 불변 JSON 문자열로 보존해 차후 화면 어댑터에 전달할 수 있다.

- 새 목록/정렬/기간/계정/코스 변경, 새 선택·취소·폐기 시 이전 준비 자료를 비우고 늦은 응답은 무시한다.
- 페이지 추가 실패는 이미 받은 목록과 커서를 유지한다. 재시도는 실패한 목록/추가 페이지/선택 요청을 반복한다.
- 재생 불가·삭제 404·네트워크 오류·코스/버전/기록/시간 불일치는 준비 완료로 넘기지 않는다.
- 화면을 붙이는 쪽은 인증 회원·코스 변경 시 changeContext를 호출하거나 이전 controller를 dispose하고 새로 만들어야 한다. 기존 AuthInterceptor도 요청의 runOwner를 검사한다.
- 준비 자료는 메모리 상태이며 시작 승인·시작 후 고정 스냅샷이 아니다. 시작 직전 코스 상태·상대 사용 가능성을 서버가 다시 확인하는 절차는 이후 구현한다.

WdAppBar·WdTabBar·WdFilterChip·WdStatSummary·WdMyRankCard·WdSectionHeading·WdRankList·WdInfoBanner·WdButton과 기존 토큰/로컬 아이콘을 재사용한다. 기간 필터, 전체 요약, 최고 카드, 최근순 과거 기록, 더 보기, 품질/오류/빈 상태와 준비 완료 CTA를 제공한다. 다른 러너 탭은 onOtherRunners 연결 전까지 조작하지 못하게 한다.

피그마의 “모두 고스트로 쓸 수 있어요”는 확정 품질 제한과 맞지 않아 선택 시 적합성을 확인한다는 문구를 사용한다. 상태바는 OS/SafeArea에 맡긴다. 긴 코스명은 앱바에서 축약하고 좁은 화면은 섹션의 보조 문구를 생략한다. 402/320 폭의 선택·준비·품질 제한·빈 상태를 검증한다.
