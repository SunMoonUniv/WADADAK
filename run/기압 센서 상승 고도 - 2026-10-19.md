# 기압 센서 상승 고도 · RESULT_V3

2026-10-19 사용자 요청: 기압 센서가 있는 기기는 센서를 사용해 상승 고도를 계산한다. 센서 없는 기기의 고도 DB 보정은 후속 작업이다.

## 정책과 범위

- 개발 정책 v3 1.1·4.5·6.6·9장: 오프라인 측정, 기기 원본 우선 저장, 종료 후 업로드, 서버 재계산, 원본·기존 거리/시간·등록 시각 보존을 따른다.
- `run 패키지 정리 - 2026-10-16.md`의 위치를 따른다. 입력 DTO는 `run/internal/RunContracts`, 지표는 `internal/metrics`, 업로드 검증은 `internal/recording`이다. `GpsQuality` 및 코스 판정의 규칙을 바꾸지 않는다.
- Android 우선이다. 기존 위치 foreground service와 wake lock이 유지되는 동안 기압을 수집한다. 센서가 없는 기기를 필수 하드웨어 조건으로 제외하지 않는다. 화면 이동과 분리하며 일시정지·종료·로그아웃·저장 실패·controller 종료 때 센서를 해제한다.
- 고도 DB/API, 날씨 기반 보정, 기압 고도의 GPS 보정, 코스 등록 고도 프로필은 추가하지 않는다. 당시 제외한 라이브 누적 고도는 2026-10-20 사용자 요청으로 허용하며 정책 문서 공통 2와 [실시간 고도·PACE_V3 계약](<실시간 고도와 균형형 GPS 보정 - 2026-10-20.md>)을 따른다.

## 원본 계약

- `BAROMETER` 입력을 GPS·걸음·조작 이벤트와 같은 단일 순번 스트림에 추가한다. `pressureHpa`는 실제 센서 기압(hPa), `pressureAccuracy`는 Android의 0~3 상태 코드다. 이를 m 단위 정확도로 간주하지 않는다. 0(신뢰 불가)도 원본에 보존한다.
- `elapsedMs`·`measuredAt`은 기존의 입력 수신 시각 계약을 유지한다. 실제 측정 시각은 `sampleEndMs`에 러닝 시작 기준 단조 시각으로 보존한다. Android `SensorEvent.timestamp`와 기존 `elapsedRealtime`은 같은 시간 기준이다.
- 약 1Hz 수집을 요청하고 최신 측정을 중복 없이 가져온다. 미래·2초 초과 지연·중복/역순·시작 전·일시정지 전 표본의 뒤늦은 수신을 새 이동 구간의 표본으로 저장하지 않는다. 2초는 초기 수신 신선도 상한이다.
- SQLite `inputs.payload`와 서버 `run.inputs.payload` JSON 확장이다. 테이블 구조·DB 버전은 그대로이며 원본 압력을 GPS의 `altitudeM`에 덮어쓰지 않는다. 동일 순번의 압력/정확도/센서 시각이 바뀐 재업로드는 충돌이다.
- `BAROMETER`는 GPS 이동 확인 창을 초기화하지 않는다. 거리·시간·PACE_V2·랩·케이던스·자동 재개·코스 판정에는 압력을 사용하지 않는다. 서버에 이미 있는 `SEGMENT_END`를 앱도 같은 이름으로 읽고 쓰며 자유 러닝 이동 창에서는 무시한다.

## 계산

- 통계 버전만 `RESULT_V3`로 올린다. PACE·완주·랭킹 정책 버전은 유지한다. 앱/서버가 동일한 원본을 재생한다.
- 확인된 연속 이동 구간별로 기압 자료를 우선 사용한다. 분석 가능한 기압 블록(3개 이상·2초 이상)이 전혀 없으면 그 이동 구간 전체에 기존 RESULT_V2 GPS 고도 계산을 적용한다. 기압을 일부 계산할 수 있는 구간에서는 빠진 부분을 GPS로 이어 채우지 않고 일부 측정으로 표시한다.
- 압력은 `44330 × (1 - (pressureHpa / 1013.25)^(1 / 5.255))`로 표준대기 고도로 변환한다. 상대 높이 차이만 사용하며 절대 해발 고도의 정확성을 보장하지 않는다.
- 분석에는 유한한 300~1100hPa 및 상태 1~3을 사용한다. 범위 밖이나 신뢰 불가 상태는 블록을 끊는다. 이는 분석용 초기 품질 범위이며 유한한 양수의 측정 원본 수집 범위를 줄이지 않는다.
- 10초 초과 표본 공백·잘못된 시간 간격·3m/s 초과 수직 변화는 블록을 끊고 튄 표본을 다음 기준점으로 사용하지 않는다. 일시정지·확인된 정지·GPS 공백 전후의 높이도 잇지 않는다. 센서 측정 시각의 수평 거리는 같은 연속 GPS 이동 구간 안에서 누적 거리로 보간한다.
- 기존 5초 중앙값·5초 지속 골짜기/봉우리·5초/수평 5m 확인·경사 시작/종료 보완을 재사용한다. 기압은 최소 1.5m 상승/반전 기준을 사용한다. 기압 상태나 센서 해상도를 가짜 m 정확도로 바꾸지 않는다. GPS 경로는 기존 양 끝 고도 정확도 합/미상 10m 규칙을 그대로 따른다.
- 구간별 상승량을 합산한다. 데이터 원천이 바뀔 때 절대 높이 차이를 상승량으로 더하지 않는다. 결과 `elevationSource`는 `BAROMETER`, `GPS`, `MIXED`, 측정 불가 시 null이다. 계산 가능하지만 상승이 없으면 0m, 자료 부족은 null(`—`), 일부 자료만 있으면 `elevationPartial`이다.

## 저장·표시·배포

- 확정 결과 stats는 종료 시 계산/캐시하고 원본과 분리한 종료 요약에 보존한다. 2026-10-20 확장으로 러닝 중에는 별도 잠정 고도를 약 3초 간격으로 계산·표시하며 이 값으로 원본이나 종료 stats를 덮어쓰지 않는다. 목록에서 전체 원본을 읽지 않는다. 결과 화면에는 기압 사용 여부 또는 구간별 두 원천 사용 안내를 기존 디자인 시스템 글꼴·색으로 표시한다.
- 이전 stats는 원본이 있으면 상세에서 V3로 보완한다. 서버 상세 GET은 기존 결과 JSON·최초 등록 시각·이벤트·랭킹을 다시 쓰지 않는다. 과거에 수집하지 않은 압력은 복원하지 않는다.
- **새 서버를 먼저 배포한 뒤 새 앱을 적용한다.** 이전 서버는 새 입력 종류를 모를 수 있다. 구현 완료와 배포·실기기 정확도 검증은 구분한다.
- 장시간 날씨 변화나 압력 포트 가림에 따른 느린 오차를 완전히 제거하는 기능은 없다. 알려진 평지와 작은 언덕에서 실제 기기·착용 위치·날씨별 검증 후 품질 수치를 조정한다.
