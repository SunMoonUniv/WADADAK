# 고스트 조회 최적화·센서 분리 · 2026-11-02

요청: 기존 정책과 동작을 유지하면서 코드 품질 검토에서 확인한 반복 계산·조회 비용을 줄이고 책임을 정리한다.

## 변경

- 앱 `GhostRunContext`: 생성 시 검증한 불변 재생을 보관해 getter에서 JSON 디코딩·객체 생성·재인코딩을 반복하지 않는다. 승인 원문 보존과 방어적 JSON 반환은 유지한다.
- `FreeRunScreen`: 실시간 상태의 build에서 고스트 격차를 한 번 계산하고 위치·거리·시간 표시에 재사용한다. 준비·결과 화면에서는 계산하지 않는다.
- `RunSensorSession`: 센서 시작·표본 수집·기압/걸음 센서 해제를 분리한다. 컨트롤러는 권한 검사, 기기 저장, 음성·종료 순서와 단일 수집 작업 관리를 유지한다. 중단·계정/세션 변경 후 늦게 도착한 표본은 수용하지 않는다.
- 서버 `GhostResultService`: 결과 조회 권한은 등록 시도의 존재 또는 자유 대결 소유권으로 확인하며 경로 엔티티나 자유 대결 전체 승인 자료를 해석하지 않는다.
- `GhostComparisonStore`: 비교 결과와 원본 현재 상태를 한 번에 조회한다. DB 안에서 context JSON을 한 번 해석하고 결과·상태만 전달한다. 결과 읽기에 전체 재생 객체를 만들지 않는다. 승인 스냅샷의 본인 센서·PB 계산은 작은 메서드로 나누고 같은 경로의 JSON 변환도 재사용한다.
- `OwnGhostCandidates`: 한 번 구한 후보 집합을 전체 요약·최고 기록·현재 페이지에서 재사용한다. 빈 페이지여도 전체 요약을 제공한다.

## 유지하는 계약

- API 주소·요청·응답, DB 스키마, 저장된 승인·원본·최종 판정 형식은 유지한다. 새 마이그레이션이나 기존 데이터 재계산은 없다.
- 완주·거리·정수 초 승패·공백 처리·기록별 재생 버전·공개 기간·원본 고정·60초 복구 조건은 유지한다.
- 권한은 본인 결과에 한정하며 공개 상대 센서 자료를 추가 노출하지 않는다.
- 원본 현재 상태 우선순위는 탈퇴 → 삭제 → 공개 상대의 비공개 → 사용 가능이다. 대결 당시 비교와 승패는 보존한다.
- 과거 상세 없음은 기존 `LEGACY_NO_DETAIL`을 유지하며 없는 상세를 추정하지 않는다.
- 내 후보의 전체 요약, 기간, 최고/최근 정렬, 동률 순서, 버전·경로 호환 조건, 커서와 회원 잠금은 유지한다. 후보를 구하는 SQL 실행만 통합한다.
- 센서 미지원·센서 고장은 GPS 측정을 중단하지 않고, 내구 저장 실패는 기존 오류 경로로 전달한다.
- 코스 선택 C8의 저장한 코스·내가 만든 코스와 북마크 API는 이번 작업에 포함하지 않는다.
