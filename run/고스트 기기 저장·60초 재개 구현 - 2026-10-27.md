# 고스트 기기 저장·60초 재개 구현 · 2026-10-27

브랜치: `feature/F09-ghost-recovery`, 기반 `14ab1bf`(고스트 시작 승인). 기존 시작 승인 PR은 수정하지 않는다. 이번 변경은 로컬 구현이며 커밋·push·PR·운영 적용을 수행하지 않았다. 기존 미추적 문서 11개를 보존했다.

## 이번에 연결한 범위

서버 승인에 이어 시작 요청/코스/상대/승인을 기기에 저장하고, 프로세스 재실행 때 동일 대결을 복원한다. 기존 OwnGhostSelectionView의 onPrepared 결과를 `RunController.selectGhost(PreparedOwnGhost)`에 전달하면 기존 코스 준비→출발점→카운트다운에서 고스트 시작 승인 API를 사용한다. 별도 course/start나 새 세션을 만들지 않는다. 선택 메뉴/라우터 연결, 지도 고스트 표지/격차 UI, 서버 승패·공개 상대는 계속 후속이다.

일반 자유·코스 러닝은 종전처럼 마지막 checkpoint에서 INTERRUPTED로 마감한다. 신뢰할 수 있는 고스트 시작 문맥이 있는 미종료 세션에만 새 재개 규칙을 적용한다. 기존 측정기·CourseTracker·위치 스트림·센서/음성·동기화기를 재사용한다.

## 시작 원장과 원자적 저장

- `GhostStartIntent`: owner/sessionId/startedAt/course ID·버전·경로·거리/sourceRecordId·비교 초/OS 시작 시계. POST 전에 SQLite에 불변 값으로 저장한다. 요청 재전송에서 ID·startedAt·상대를 바꾸지 않는다.
- `GhostRunContext`: 응답의 승인/세션/상대/코스 경로·거리·버전/시작 시각/재생 버전·적합성을 요청과 대조한다. 응답 불일치는 측정 시작으로 이어지지 않는다.
- 승인 응답은 우선 시작 원장에 저장한다. 로컬 START와 sessions의 전체 문맥 저장 및 원장 제거는 하나의 SQLite 트랜잭션이다. START 삽입 실패 시 승인 원장이 남고 빈 세션은 남지 않는다.
- 시작 성공 여부가 불명확한 원장은 새 자유/코스 시작을 막는다. GET으로 같은 승인을 확인하며, GET 404도 아직 진행 중인 POST의 취소를 뜻하지 않는다. 신뢰 가능한 원장 저장 시점에서 60초 이내에만 같은 POST를 재시도한다.
- 60초 초과/재부팅 상태에서 GET 404이면 기존 삭제 예약으로 원장 ID를 취소하고 서버 삭제를 재전송한다. 늦은 승인 응답이 해당 ID를 부활시키지 못한다. GET에서 이미 승인된 사실을 확인하면 새로 시작하지 않고 로컬에 승인과 INTERRUPTED/0ms를 보존한다.
- 계정 전환의 늦은 응답은 새 계정의 기록에 붙지 않는다. 실행 중 명시적 계정 전환에서는 이전 계정의 미확인 원장을 삭제 예약으로 취소하고 진행 세션은 기존 ACCOUNT_CHANGED 종료를 유지한다.

## 시계·60초의 정확한 의미

Android 기존 `run_clock` 채널에 snapshot을 추가했다. `SystemClock.elapsedRealtime()`과 Settings.Global의 읽기 가능한 boot_count를 반환한다. OS 시계는 화면 잠금/절전 중에도 경과하며, 부팅 ID를 함께 비교하므로 프로세스마다 초기화되는 Stopwatch나 UTC 변경으로 재개 시간을 추정하지 않는다. 부팅 정보를 못 읽으면 null로 반환하고 프로세스 간 재개를 허용하지 않는다. 기존 elapsedRealtime 메서드와 센서 시계는 유지한다.

sessions의 recovery_anchor는 bootId/originMs/checkpointClockMs다. checkpointClockMs=originMs+checkpoint_ms를 같은 쓰기로 보존한다. 입력 삽입 또는 checkpoint 갱신 실패는 창을 연장하지 않고 마지막 성공 저장을 유지한다.

재개 조건은 같은 부팅 ID, 시계 역행 없음, 저장 문맥/세션/시작 시각 일치, 마지막 저장 후 **0~60,000ms 포함**이다. 총 소요시간은 원래 originMs에서 계산한다. 60,001ms·재부팅·시계 불명확/조회 실패이면 기존 checkpoint 시각에 INTERRUPTED를 추가한다. 원본·시작 시각·세션 ID·상대·계산 버전은 바꾸지 않는다.

아직 START가 없는 원장은 저장된 시작 시계로 판단한다. 정상 60초 창 안에서 최초 승인 응답을 저장했으면 그 승인 저장 시계가 다음 복구 지점이 된다. 같은 승인 재조회만으로 이 시계를 계속 갱신하지 않는다. 늦게 받은 GET 응답이 이미 만료된 미확인 요청의 재개 창을 새로 열지도 않는다.

## 복구 상태·경로·업로드

- 재개 때 저장 checkpoint부터 새 OS 시각까지 PROCESS_RECOVERY GAP 입력을 남긴다. 표본·거리·고도·걸음을 생성하거나 직선 연결하지 않는다. 다음 유효 GPS는 새 연결의 첫 점이다.
- 입력 seq는 이어 붙이고 START는 하나다. running/paused를 유지하며, paused 복구 자체가 RESUME를 만들지 않는다. 상대 재생에는 같은 총 소요시간을 전달하므로 중단·내 일시정지 중에도 상대는 진행한다.
- 코스/상대 자료는 기기 저장에서 읽는다. 이미 기록된 SEGMENT_END를 복원해 종료된 코스 대결을 다시 열지 않으며, 남은 같은 세션은 자유 러닝이다. 추적기는 기존 원본으로 재구성하고 과거 이탈 팝업·음성을 다시 재생하지 않는다.
- 복구 자체는 서버 시작/도전 수 이벤트를 새로 보내지 않는다. 알려진 승인이 있으면 오프라인에서도 재개할 수 있다. 승인 자체가 불명확하고 서버에 연결할 수 없으면 원장을 보존하고 새 측정을 시작하지 않는다.
- 종료/구간 종료는 ghost_closures에 같은 트랜잭션으로 보존한다. 동기화기는 종료 신호를 재시도한 뒤 기존 세션 ID/startedAt/입력으로 업로드한다. 측정 거리 0이라 업로드 대상이 아니어도 종료 신호는 남는다. 본인 삭제 시 종료 대기 행은 FK CASCADE로 지워진다.

## SQLite v4와 공동 리뷰

파일명 runs_v1.db는 유지한다. sessions에 ghost_context/recovery_anchor TEXT를 추가하고 ghost_start_intents(계정당 하나의 측정 전 요청)/ghost_closures를 만든다. v1→v2→v3 이관을 유지하며 기존 원본·결과·최초 등록 시각·삭제 예약은 보존한다. 목록 조회는 큰 승인/재생 JSON을 읽지 않는다. [DB 구조](<../DB 구조.md>)에 반영했다. 서버 DTO·DB·이벤트 계약 변경은 없다.

새 파일: ghost_run 모델, GhostStartApi(기존 인증된 Dio/runOwner 재사용), GhostStartFlow, 테스트/지원 자료. 공유 변경: RunController/Recorder/LocalStore/SyncWorker, LocalRun·CourseSnapshot의 추가 선택 필드, core/time와 Android MainActivity. F5/F6 측정·복구·삭제 회귀와 core/Android 시계 변경은 공동/전원 리뷰 대상이다. 담당자 승인이나 메시지 발송을 완료한 것으로 표시하지 않는다.
